# 장애 인계 요약 (incident-handoff)

다른 Agent나 사람이 **처음부터 다시 조회하지 않고 이어서 일할 수 있게** 지금까지의 대화를 요약한다.

## 작성 순서

1. 이 장애의 `incident_id`를 첫 줄에 쓴다. 받는 쪽은 이 값으로 `get_incident`를 호출한다.
2. 대화에서 **조회 도구로 확인한 사실**만 골라 시각과 값을 함께 적는다. 운영자의 짐작은 사실에 넣지 않는다.
3. 추정은 따로 적고, 왜 그렇게 봤는지 한 줄로 붙인다.
4. 이미 요청하거나 실행한 조치와 그 상태를 적는다. `get_action_status`로 최신 상태를 확인한 뒤 적는다.
5. 받는 쪽이 답해야 할 질문을 구체적으로 적는다. 예: "DB 커넥션 풀 고갈 여부와 10:40 이후 슬로 쿼리 확인"
6. 아래 형식을 지킨다. 전체 20줄을 넘기지 않는다.

## 형식

```text
[인계] incident_id: {incident_id}
대상: {서비스} / {호스트}, 감지 {detected_at}
받는 쪽: {전문 Agent 이름 또는 담당 영역}

확인한 사실
- {시각} {내용과 값}
- ...

추정
- {추정} (근거: {한 줄})

조치 이력
- {조치 ID} {요청 / 승인 대기 / 실행 완료 / 거절} ({시각})
- 없음

받는 쪽에 요청하는 확인
1. {질문}
2. {질문}
```

## 하지 않는 것

- 로그 원문을 길게 붙이지 않는다. 받는 쪽이 직접 조회할 수 있다.
- 비밀 값(API Key, 토큰, 비밀번호)을 요약에 넣지 않는다.
