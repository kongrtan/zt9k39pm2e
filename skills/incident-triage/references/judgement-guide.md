# 판단 기준

## 심각도

| 심각도 | 기준 |
|---|---|
| `CRITICAL` | 사용자 요청 실패(5xx, 타임아웃)가 늘고 있거나, 임계치 초과가 15분 이상 지속되며 상승 중 |
| `WARNING` | 임계치는 넘었지만 오류 증가가 없거나, 하강 추세 |
| `NORMAL` | 현재 임계치 아래로 돌아왔고 오류도 없음 (일시적 급증) |

## 확신도 (confidence)

| 값 | 기준 |
|---|---|
| 0.8 이상 | 시각이 맞는 근거가 두 가지 이상 (예: 배포 시각 = 오류 시작 시각, 같은 패턴의 과거 장애) |
| 0.5 ~ 0.8 | 근거가 하나이거나, 시각은 맞지만 직접 원인을 보여주는 로그가 없음 |
| 0.5 미만 | 근거 없음, 추정만 가능. 이때는 `NONE`을 추천 |

## 자주 나오는 패턴

| 패턴 | 확인할 것 | 흔한 원인 |
|---|---|---|
| 배포 직후 오류·자원 급증 | 배포 시각과 `breach_started_at` 비교 | 신규 코드 결함, 설정 누락 |
| 메모리가 계속 오르고 GC 로그 증가 | `trend_last_5 = rising`, OOM 로그 | 메모리 누수 |
| 특정 시각마다 반복 | 과거 같은 시각의 장애 | 배치 작업, 정기 백업 |
| 여러 서비스가 동시에 | 공통 의존 대상(DB, 캐시, 네트워크) | 하위 의존 장애 → 전문 Agent 전환 제안 |
