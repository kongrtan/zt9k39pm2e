# 조치 화이트리스트

Agent가 추천하거나 `request_action`으로 요청할 수 있는 조치는 이 표에 있는 것뿐이다.
실제로 실행할지는 오케스트레이터의 정책 표와 사람의 승인으로 정한다.

| 조치 ID | 내용 | 파라미터 | 위험도 | 쓰는 경우 |
|---|---|---|---|---|
| `RESTART_SERVICE` | 서비스 인스턴스 재시작 | `service`, `host` | 중 | 메모리 누수, 스레드 고갈, 응답 없음이 확인되고 재시작 외 대안이 없을 때 |
| `SCALE_OUT` | 인스턴스 수 증가 | `service`, `count` (1~3) | 중 | 트래픽 증가로 인한 자원 부족. 오류 증가 없이 부하만 높을 때 |
| `CLEAR_CACHE` | 애플리케이션 캐시 초기화 | `service`, `cache_name` | 하 | 배포 후 캐시 불일치로 보이는 오류 |
| `ROLLBACK_DEPLOY` | 직전 배포로 되돌림 | `service`, `deploy_id` | 상 | 감지 직전 배포가 있고, 오류가 배포 시각부터 시작됐을 때 |
| `NONE` | 조치 없음, 사람 확인 필요 | 없음 | - | 원인이 불명확하거나 확신도 0.5 미만 |

> 이 표는 샘플이다. 실제 조치 목록과 파라미터는 오케스트레이터의 정책 표와 맞춘다.
