# 에스컬레이션과 전문 Agent 전환 기준

개인 이름과 연락처는 넣지 않는다. 역할과 채널만 적는다. 실제 연락은 오케스트레이터가 조직도에서 찾는다.

## 1. 전문 Agent로 전환을 제안하는 경우

| 확인된 상황 | 제안할 전문 Agent | 넘길 때 함께 요청할 확인 |
|---|---|---|
| 슬로 쿼리, 락 대기, 커넥션 풀 고갈 로그 | `db-agent` | 감지 시각 전후 슬로 쿼리 상위 10개, 락 대기 세션 |
| 여러 서비스에서 동시에 타임아웃, 외부 연동 실패 | `network-agent` | 구간별 지연, 방화벽·게이트웨이 오류 |
| 캐시 적중률 급락, 메시지 큐 적체 | `middleware-agent` | 캐시 메모리, 축출 건수, 큐 적체량 |
| 애플리케이션 예외, 배포 직후 오류 | `app-agent` | 배포 변경 내용, 예외 스택 상위 3개 |

전환할 때는 `incident-handoff` 스킬로 인계 요약을 만든다.

## 2. 사람에게 에스컬레이션하는 경우

| 조건 | 대상 (역할) | 채널 |
|---|---|---|
| `CRITICAL`이 15분 넘게 해결되지 않음 | 서비스 담당 팀 리드 | 장애 채팅방 + 메신저 개인 알림 |
| Tier 1 서비스의 `ROLLBACK_DEPLOY`가 필요함 | 서비스 담당 팀 리드 + 변경 관리 담당 | 승인 요청 (2인 승인) |
| 원인 확신도 0.5 미만이 30분 지속 | 당직 엔지니어 | 메신저 개인 알림 |
| 외부 결제대행사 장애로 보임 | 결제개발팀 + 대외 협력 담당 | 장애 채팅방 |

## 3. Agent가 하지 않는 것

- 사람에게 직접 연락하지 않는다. 에스컬레이션이 필요하다고 **운영자에게 알리고**, 실제 발송은 오케스트레이터가 한다.
- 승인 권한이 누구에게 있는지 판단하지 않는다. 승인 카드에 표시되는 대로 안내한다.
